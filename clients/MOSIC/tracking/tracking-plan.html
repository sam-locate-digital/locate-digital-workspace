MOSIC — conversion tracking plan

Date: 2026-06-23 · Tier: GA4 + GTM (Growth) · CMS: WordPress (WPBakery) · Booking: Cliniko · Import: Google Ads (live), Meta (staged)
Context: MOSIC runs Google Ads but has no verified conversion tracking. This closes the "set up conversion tracking audit before next spend cycle" item. Right now spend can't be tied to bookings — the account is flying blind.

Measurement plan

Three real entry points: phone calls, website enquiry forms, and Cliniko online bookings. Telehealth books through the same Cliniko flow.

EventFires whenValuePrimary?

booking_confirmedCliniko booking completes (see limitation)new-patient value✓

Value to assign: set one new-patient value so Google optimises to revenue, not clicks. Osteo initial consults run ~$110–130. Recommend $120 (first-visit value) — conservative and defensible. Confirm with MOSIC; if they share average new-patient lifetime value from Cliniko, use that.

GA4 setup

  1. Confirm one GA4 property (not duplicated). Record the Measurement ID.
  2. Create key events: phone_call, form_submit, booking_start, booking_confirmed, generate_lead.
  3. Mark the primary events as key events / conversions.
  4. Link GA4 → Google Ads for import + audience sharing.
  5. Data retention 14 months. Google signals only if consent allows.

GTM setup

GTM is cleanest here — WordPress site with several actions to track. Install a container if none is live.

phone_call

Trigger: Click — Just Links, Click URL contains "tel:"
Tags: GA4 event phone_call {value:120, currency:AUD}
      Google Ads conversion [Phone call label]
      Meta pixel Lead  (staged, paused)

form_submit

Trigger: form plugin submit-success event,
         or thank-you page view (Path = /thank-you)
Tags: GA4 form_submit {value:120, currency:AUD}
      Google Ads conversion [Lead form label]
      Meta pixel Lead  (staged)
Note: confirm which form plugin MOSIC uses — it sets the method.

booking_start (Cliniko)

Trigger: Click — Just Links, URL contains the Cliniko booking domain
         (confirm exact: e.g. mosic.au1.cliniko.com)
Tags: GA4 booking_start
booking_confirmed limitation: Cliniko's booking runs on its own domain — GTM on the MOSIC site can't see a completed booking. Options, best first: 1) if Cliniko can redirect to a MOSIC thank-you URL, fire booking_confirmed on that page view; 2) reconcile bookings via the Cliniko API in the monthly report (accurate, offline); 3) use booking_start as the proxy for now. Launch on the proxy, pursue option 1.

Platform conversions

Google Ads (active): import GA4 primary key events as conversions (single source of truth). Categories: phone_call → Phone calls; form_submit → Submit lead form; bookings → Book appointment. Optimise to the strongest confirmed signal.

Meta (staged): pixel + standard events written into GTM but paused. Flip on when MOSIC starts Meta. Lead for forms/calls, Schedule for bookings.

Server-side

Not in scope at Growth. Flag to MOSIC as a Scale upgrade — server-side GTM + enhanced conversions would recover iOS/ad-blocker loss. Park as an upsell.

Consent & privacy

  • If a consent banner exists, set up Consent Mode v2 — tags wait for consent, GA4 models the gap.
  • Health sensitivity: never pass condition/treatment/patient detail into events. Track that a booking happened, never what for.
  • No raw email/phone in any payload. If enhanced conversions go on later, confirm Google is hashing, not sending plain.
  • Australian Privacy Act applies — match MOSIC's privacy policy; if it omits analytics/ad cookies, flag to update.

QA checklist — the gate

Run before the next spend cycle. Every line passes, or tracking is broken.
